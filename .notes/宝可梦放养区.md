# 宝可梦放养区（侧栏挂件）

侧栏里那格「宝可梦放养区」：**每次打开网页**随机放一只喜欢的宝可梦在栏里走动、
时不时跳一下；点一下可以摸它 —— 它会换成笑脸、蹦两下、说一句话；平常浏览的时候
过一会儿它也会自己嘟囔一句，台词按「当前页面 / 访客当地天气 / 深夜」分池挑。
**它还会睡**：到了它的睡觉时段（或者你在同一个页面赖太久）就会趴下睡，戳一下叫醒它。
围栏右上角常年挂着两个半透明的小图标，表示外面的天气和现在的时间（早/中/晚/夜）。

- 同一个标签页里翻页**不会换**（存在 `sessionStorage`），关掉标签页重新打开才会重抽。
- 素材是 PMD（宝可梦不可思议迷宫）风格的行走图和脸图，来自
  [PMD Sprite Repository](https://sprites.pmdcollab.org/)（PMDCollab/SpriteCollab），
  许可是 **CC BY-NC 4.0**（非商业 + 署名），详见下面「授权」一节。

## 二、怎么改

三个命令，按你改了什么选一个：

```sh
python tools/build-pkmn.py            # 全量：下载素材 + 重拼精灵表 + 索引 + 台词（改了名单就跑这个）
python tools/build-pkmn.py --sprites  # 只重做精灵表 / 草地 / 图标（改了 sleep 作息就跑这个）
python tools/build-pkmn.py --talk     # 只重生成台词 JSON（改了台词就跑这个，不联网、一秒）
```

⚠️ 两个都跑完记得 `git add -A && git commit && git push`，GitHub Actions 那边会自动发布。

### 1. 换收藏名单

编辑 `data/pkmn-pool.toml`（`dex` = 全国图鉴编号，`name` = 显示名），然后：

```sh
python tools/build-pkmn.py        # 会重新下载素材、重拼精灵表、重生成索引
git add -A && git commit -m "放养区换名单" && git push
```

删掉一只只是不再抽到它，已经下载的素材会留在 `static/pkmn/` 里（想清干净就手动删掉
对应的 `sprite/<dex>.png` 和 `talk/<dex>.json`）。

加一只新的：往名单里加一条，然后按上面跑一遍 —— 脚本会自己去 GitHub 找它的行走图和
脸图。**如果那只在 SpriteCollab 里没有行走图，脚本会报错并告诉你**（不会悄悄生成半张图）。
脚本还会给它挑三个表情：正常 / 笑（被摸）/ 不耐烦（连着摸太多），优先
`Normal` / `Joyous` / `Worried`，没有就按预设顺序往后退（宝包茧只有 Normal，
那三个表情就是同一张图）。

### 2. 改台词

**最省事的办法：编辑器左栏「工具」→「宝可梦台词」**（选一只 → 逐句改 → 「保存并生成」，
编辑器会自动跑下面那个脚本，并把脚本输出贴在面板里；超 40 字的格子会变红）。

想自己动手改文件的话，就是编辑 `data/pkmn-talk/<图鉴号>.toml`，然后：

```sh
python tools/build-pkmn.py --talk   # 只重生成台词 JSON，不联网、一秒跑完
```

⚠️ **改了 TOML 不跑这个脚本，页面是不会变的** —— 网页读的是生成的
`static/pkmn/talk/<图鉴号>.json`，不是 TOML（全部 35 只的台词加起来 100 KB 出头，
内联进页面每页都得背；所以改成「点开哪只才下载哪只」）。

脚本会顺手校验：缺少哪一段、哪句超长、哪句里有引号括号 emoji、哪只内部有重复句，
都会直接报错并把那句话打出来，不会把坏数据放进站点。
（编辑器那个面板读写的是同一批 TOML，只是帮你省了记格式和跑脚本两步 ——
它保存时会按统一格式重写整个文件，首行那条 `# 330 沙漠蜻蜓 Flygon` 注释会留着，
其它位置本来也没有注释。）

### 3. 台词文件的格式

```toml
name = "沙漠蜻蜓"

pet = [                 # ≥6 条（实际写到 8）：被摸时说的
  "唔……翅膀有点痒。",
]
pet_more = ["…"]        # 可选 ≥2 条：连着摸第四次起说的（受不了 / 嘴硬 / 害羞）
idle = ["…"]            # ≥9 条（实际 12）：平常自己嘟囔
night = ["…"]           # 可选 ≥2 条（实际 3）：深夜（22:00–06:00）醒着时说的
sleepy = ["…"]          # ≥2 条（实际 3）：打瞌睡前说的（说到一半就睡着的感觉）
sleep = ["…"]           # ≥2 条（实际 3）：睡着时的梦话（可以断断续续）
wake = ["…"]            # ≥2 条（实际 3）：被戳醒时说的（含糊、还没缓过来）

[page]                  # 页面语境。home/about/blog/diary/nav 各 ≥3 条（实际 4）；
home = ["…"]            # gallery / tbtak / other 可选（实际 2~3）
about = ["…"]
blog = ["…"]
diary = ["…"]
nav = ["…"]

[weather]               # 访客当地天气。clear/cloudy/rain/snow/thunder 各 ≥2 条（实际 3）；
clear = ["…"]           # fog / drizzle 可选（实际 2）
rain = ["…"]
```

硬规矩（脚本会拦）：

- **一句不超过 40 字**，建议 8~24 字 —— 台词框只有 3 行、一行约 16 字。
- 台词里不要有引号、书名号、括号、emoji、颜文字，也不要写「沙漠蜻蜓：」这种前缀，
  对话框只显示这句话本身。
- 顶层键只能是上面这几个；`page` / `weather` 下的键名不能写错。
- ⚠️ **TOML 的坑**：`night`、`pet_more` 这些顶层键必须写在所有 `[段]` 之前。
  写在 `[weather]` 后面会被解析成 `weather.night`，脚本会报「weather 里不认识的键」。

`?pkmn=445&pkmn-debug=1` 打开调试模式后，可以在控制台里 `__pkmn.pool()` 看当前这一页
到底会从哪些句子里抽（返回的就是带权重的候选池）。

### 4. 台词是怎么挑的

一次自言自语时的候选池（同一句不会连着出现）：

| 池 | 权重 | 什么时候进池 |
| --- | --- | --- |
| `page.<当前页面>` | ×3 | 总是。页面类型由 `layouts/baseof.html` 写进 `<body data-pkmn-ctx>`：`home` 首页 / `about` 关于 / `blog` 博客与文章 / `diary` 日记 / `nav` 导航 / `gallery` 画廊 / `tbtak` 始祖小鸟专题页 / `other` 其它（标签页、404 等） |
| `weather.<当前天气>` | ×2 | 查到了天气时。`drizzle` 缺就退到 `rain`，`fog` 缺就退到 `cloudy` |
| `night` | ×2 | 醒着、且本地时间 22:00–06:00 |
| `idle` | ×1 | 总是（底噪） |
| `sleep`（梦话） | —— | **睡着时只从这个池抽**，间隔也拉长到 35~80 秒 |

两句之间的间隔是 22~48 秒随机，打开页面约 4 秒后先说第一句。
被摸时从 `pet` 里抽（连着摸第 4 次起改抽 `pet_more`）；
快睡着时说 `sleepy`；被戳醒时说 `wake`。

### 5. 作息：什么时候会睡

每只在 `data/pkmn-pool.toml` 里有个 `sleep` 字段：

| 写法 | 意思 | 现在给了谁 |
| --- | --- | --- |
| `sleep = "night"`（默认，不写就是这个） | **夜里睡**、白天活动 | 其余 27 只 |
| `sleep = "day"` | **白天睡**、夜里活动（夜行性） | 勾魂眼、电灯怪、诅咒娃娃、黑夜魔灵、水晶灯火灵、伊裴尔塔尔、狙射树枭、谜拟丘 |

- **睡觉时段**：夜里 = 22:00–06:00，白天 = 06:00–22:00。
- 打开页面时，如果正好是它的睡觉时段，**78% 概率已经在睡**；没睡的过 25 秒才可能开始困
  （先给一句招呼的时间）。
- **在同一页赖着不走**超过 10 分钟也会打瞌睡（`DOZE_MINUTES`）。
- 困的时候先说一句 `sleepy`，约 4.5 秒后趴下；睡着时不动、不蹦，头顶飘 Z，台词换成梦话。
- **戳一下就醒**：换「惊醒」表情（脸图第 4 个槽）、蹦两下、说一句 `wake`。
  醒来能撑 2~6 分钟，要是还在它的睡觉时段就再睡回去。
- 想改谁白天睡谁夜里睡：改 `data/pkmn-pool.toml` 的 `sleep`，然后跑 `python tools/build-pkmn.py --sprites`。

## 三、精灵表是怎么来的

PMDCollab 的每一个宝可梦是一堆分开的图：`sprite/<图鉴号>/Idle-Anim.png`、
`Walk-Anim.png`、`AnimData.xml`、`portrait/<图鉴号>/<表情>.png`。
其中动画表是**一行一个方向**（PMD 固定 8 行：下、右下、右、右上、上、左上、左、左下），
一列一帧，格子大小写在 `AnimData.xml` 的 `FrameWidth`/`FrameHeight`，
每帧时长也在里面（单位是 1/60 秒）。

`tools/build-pkmn.py` 只取走放养区需要的部分，重新拼成**一只一张**的精灵表：

```
第 0 行  Idle（方向=下，面向访客）
第 1 行  Walk 左（方向=左）
第 2 行  Walk 右（方向=右）
第 3 行  脸图 40×40（列号见 index.json 的 f.c：正常 / 笑 / 不耐烦 / 惊醒）
第 4 行  影子（只有第 0 列，脚本按身体宽度画的硬边点阵椭圆）
第 5 行  Sleep（睡觉动画，方向=下）
```

每一格是 `cellW × cellH` 美术像素，所有帧**底边对齐**（脚踩在同一条线上），
裁切按「整组帧的并集」做一次 —— 这样帧与帧之间的相对位移（走路时的起伏）保住了，
又去掉了四周的空白。

> 方向行索引核对过：把每两行做「镜像相似度矩阵」，结果是镜像第 1 行 ≈ 第 7 行、
> 镜像第 2 行 ≈ 第 6 行、镜像第 3 行 ≈ 第 5 行、第 4 行自身最对称 —— 和 PMD
> 的资料（「row 0 = Down, row 2 = Right, row 4 = Up, row 6 = Left」）一致。
> 拼好之后又验了一遍：左行 ↔ 镜像(右行) 相似度 0.81~1.00，左行 ↔ 右行 只有 0.19~0.57，
> 说明左右确实是两个方向、没有取错行。

### 页面上的放大倍数

**点阵锐利的前提和站里点阵字体是同一条：美术像素 × 整数 = 设备像素。**

- 画布 `width/height` 直接设成设备像素数，CSS 尺寸 = 设备像素 ÷ `devicePixelRatio`，
  于是浏览器把画布 1:1 贴到设备像素上，不重采样。
- 倍数按屏幕密度算：基准 `round(dpr × 1.5)`（下限 2、上限 4），
  再给「格子矮的小个子」多加一档，但永远不许超过围栏能放下的高度。
  150% 缩放下所有宝可梦都是 **3 设备像素 = 1 美术像素**；200% 时是 4。
- 元素位置用 `snap()` 吸到整设备像素 —— 150% 缩放下 1 CSS px = 1.5 设备像素，
  位置落在半像素上整张图会被重新采样一遍，点阵立刻发虚。
- 草地贴图同理：`background-size` 是 JS 按 dpr 写死的（CSS 里那个 43px 只是首屏兜底）。

实测（无头 Chrome 截图后逐块统计）：把围栏背景换成纯色单独截精灵画布，
在 100% / 150% / 200% 三档下，**「美术像素 = S×S 个同色设备像素」的相位都是 0**，
不对齐的块只有 1~1.7%（而那些块全是影子从脚下透出来的地方 —— 那是另一个点阵元素，
本来就该叠在一起）。

### 右上角那两个小图标

一格 24×24，一行深色（白天）、一行白色（夜里），整倍放大到 48 设备像素 = 32 CSS px：

| 天气 | clear 晴 / cloudy 阴 / fog 雾 / drizzle 小雨 / rain 雨 / snow 雪 / thunder 雷雨 |
| --- | --- |
| 时间 | dawn 早（05–11）/ day 中（11–17）/ dusk 晚（17–22）/ night 夜（22–05） |

- 图标来自 **HackerNoon Pixel Icon Library**（24px 那一档就是它的原生栅格），
  库里没有「纯云」和「雪」，这两个是从 `cloud-rain` 上抠的：切掉雨点就是多云，
  把雨点换成小雪花就是雪。许可见「授权」一节。
- 放在**右上角竖着叠**是有原因的：宝可梦贴着地面站、而且水平居中，
  所以两个上角它永远碰不到，不会挡到它（实测最宽的伊裴尔塔尔也只占 x 68~214，图标在 247 之后）。
- 图标是半透明的（`opacity: .72`）且不吃鼠标事件；鼠标停上去有提示（「外面：雷雨」「现在：深夜」）。
- 天气没查到就只显示时间图标。

## 四、天气是怎么判断的

`pkmnWeather = true` 时，每次打开页面（每个标签页只查一次，结果缓存 30 分钟）：

1. 先向 `https://ipwho.is/` 要一个大概的城市坐标（**这等于把访客 IP 交给这个第三方**）；
   它限流返回 429 时，退到 `https://get.geojs.io/v1/ip/geo.json`。
2. 再向 `https://api.open-meteo.com/v1/forecast?...&current=weather_code` 要一个
   WMO 天气码，映射成 7 个桶：
   `clear 晴 / cloudy 阴 / fog 雾 / drizzle 小雨 / rain 雨 / snow 雪 / thunder 雷雨`。

**任何一步失败（被墙、断网、接口改版、用户拦截）都当作「不知道天气」**，
台词就退回 `page` 和 `idle` 两池，挂件其它功能完全不受影响 —— 实测把 ipwho.is
整个拦掉，链路照样靠 geojs 走通；两家都拦掉时页面也没有任何报错。

不想让访客被查 IP 就把 `pkmnWeather` 关掉，那两个/三个请求一个都不会发。
（站里另外两个外部请求是本就有的：不蒜子访客统计、一言 API。）

## 六、已知边界

- **需要 Python + Pillow 才能重新生成素材**（`pip install pillow`）。
  素材本身就是从 GitHub raw 拉的，国内直连基本不通，跑之前先开代理：
  `$env:HTTPS_PROXY='http://127.0.0.1:7897'`。下载会缓存在 `tools/.pkmn-cache/`，
  第二次跑（或者只想 `--talk`）不需要联网。
- **`static/pkmn/index.json` 会被内联进每个页面**（这样选中之后马上就能开始下精灵表）。
  代价是每页多 ~9.5 KB（gzip 后 ~1.8 KB）。不想背就把 `pkmnPasture` 关掉。
- 每次访问实际只多拉 **1 张精灵表（5~17 KB）+ 1 个台词 JSON（3~4 KB）+ 1 张图标表（1.7 KB）**，
  实测一次完整访问的网络请求列表里确认过「精灵表请求数: 1、台词 JSON 请求数: 1」。
- 一个标签页里只放一只（翻页不换）。想换一只：关掉标签页重开，或用 `?pkmn=random`。
- **始祖小鸟那一页（`/tobitaiaaken/`）看不到放养区**：那一页为了还原老站的版式，
  用页面级 CSS 把整个侧栏 `display:none` 了，「tbtak」那池台词因此在那一页永远用不上
  （台词文件里留着，万一以后那页也要放）。同理，日记页之类如果哪天也藏了侧栏，
  放养区就跟着一起消失。
- 睡觉那套是按**访客本地时间**走的，不是按服务器时间：所以同一时刻不同的人看到的
  可能一只在睡一只在跑。
- 页面在后台标签页里时逻辑是暂停的（`document.hidden`），切回来不会「跳」一大步。
- 系统里开了「减少动态效果」（prefers-reduced-motion）时它不走来走去，只站着说话，
  台词也是直接显示、不打字机效果。
- 用 `file://` 直接打开页面时 `fetch` 拿不到台词（浏览器限制），
  本地看效果请用 `hugo server` 或编辑器里的预览。
- 挂件在窄屏（侧栏变成全宽）时围栏会跟着变宽，JS 监听 `resize` 重算尺寸；
  手机上围栏仍是 150px 高。
