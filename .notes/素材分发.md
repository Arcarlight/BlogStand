# 素材分发（GitHub 素材仓库 + jsDelivr CDN）

主站页面：`content/resources.md` → `/resources/`，正文只有一个 `{{< resources >}}`。
数据在 `data/resources.toml`，样式在 `assets/css/retro.css` 的 `.res-*` 段，交互在 `static/js/resources.js`。

## 为什么单独开一个仓库

素材（尤其是 500×500 立绘、点阵整张精灵表）会把主站仓库撑大（写这个时 `.git` 已经 152 MB，
`static/` 115 MB）。所以素材放独立仓库，主站只存一份清单：

- 素材仓库：<https://github.com/Arcarlight/Nijiboshi-Giveout-Storage>（public）
- 主站取文件的**主通道是自己的一层代理**：
  `https://nijiboshi-board.pages.dev/cdn/<路径>`
  → Cloudflare Pages Function `board-api/functions/cdn/[[path]].js` → `raw.githubusercontent.com`。
  好处：访客永远访问同一个域、永远能开；Cloudflare 边缘缓存一天，GitHub 只被打一次；
  只放行 `tbtak/{sprite,portrait,ui}/` 和 `audio/midi/` 四个前缀，不会被当成万能代理。
- **备用镜像**写在 `data/resources.toml` 的 `mirrors`：图片加载失败时页面按顺序换
  （fastly / gcore 两个 jsDelivr 节点，以及一个 GitHub 代理 ghproxy）。

### 为什么不用 jsDelivr 当主力

实测这个仓库的文件在 `cdn.jsdelivr.net` 上会 **301 跳到 `raw.githubusercontent.com`**，
国内打不开；同一时刻 `fastly.jsdelivr.net` 又可能是 200。时好时坏，所以
**主通道放自己的 Worker**，jsDelivr 只当备用。

## 素材仓库的目录约定

```
tbtak/sprite/    点阵图（行走图、战斗图，整张精灵表）
tbtak/portrait/  敌人 / 角色的小型立绘（约 500×500）
tbtak/ui/        UI 素材（图标集、窗框、按钮底图）
audio/midi/      MIDI
```

目录变了要同步改 `data/resources.toml` 里的 `file` 路径（相对素材仓库根目录）。

## 加一件素材

1. 把文件放进素材仓库对应目录，`git push`；
2. 主站 `data/resources.toml` 里加一条：

```toml
[[items]]
sec   = "sprite"                     # 归属哪个分类（sections 的 id）
title = "符利根 · 行走图"             # 卡片标题
file  = "tbtak/sprite/Fliegen-sprite-cut.png"   # 素材仓库里的相对路径
w     = 363                          # 原图宽（音频不填）
h     = 329                          # 原图高
kb    = 17                           # 文件大小，只是显示用（可以不填）
note  = "说明一句话"                  # 选填
kind  = "image"                      # 选填：image（默认）/ audio
```

3. 提交推送，GitHub Actions 部署完就出现在 `/resources/` 上。

## jsDelivr 的两个坑

1. **新文件**几分钟内可访问；**覆盖同名文件**可能还吃到旧缓存。
   想立刻生效：URL 里的 `@main` 换成 tag（如 `@v1`），或去
   <https://www.jsdelivr.com/tools/purge> 清一下。
   **最稳的做法是新版本换文件名**（`xxx-v2.png`），别覆盖。
2. 单文件别超 **20 MB**（jsDelivr 不保证；GitHub 硬上限 100 MB）。
   未缓存的文件首次请求会 301 到 raw.githubusercontent，属正常现象。

## 素材仓库里的 README / LICENSE

- `README.md` 是**给下载素材的人看的**：是什么、有什么、怎么署名、怎么下载。
  不要往里写维护步骤（那些写在本文档里）。
- `LICENSE` 是 CC BY 4.0 全文（从 <https://creativecommons.org/licenses/by/4.0/legalcode.txt> 取的）。

## 编辑器里怎么用（工具 → 素材分发）

2026-11-05 加的面板，`editor` 里的「工具 → 素材分发」。能做四件事：

1. **改页面文案**：开头三段、署名提示、授权说明、页脚补一句 —— 都存在 `data/resources.toml` 的 `[intro]` 里，
   页面从那儿读（模板只有兜底默认值，不再写死文案）。
2. **改分类**：id / 显示名 / 说明 / 整包下载链接。
3. **加素材**：点「上传素材」选文件（可多选），会
   - 写进本机的素材仓库副本（默认在主站仓库同级目录，可在面板里改位置 / 一键克隆）；
   - 自动 `git add` + `commit` + `push`，路径、宽高、KB 自动填好；
   - 新条目先落在「第一个分类」下，上传完可以改分类。
4. **仓库状态**：面板顶部会显示素材仓库路径、有没有未提交/未推的提交、用的哪个代理；
   推送失败不影响本机文件，点「推送」重试即可。

### 两个注意

- **保存只写 `data/resources.toml`**，要让页面生效还得「预览 / 发布」（发布时会一起推到 GitHub）。
- **推送代理**沿用主站仓库里配给 github.com 的那个（`http.https://github.com/.proxy`），
  读的是 `git config`，所以换电脑只要那边配好代理，素材仓库这边不用重配。
- 服务端代码在 `.editor/server.mjs`（接口 `/api/resources`、`/api/resources/upload`、`/api/resources/repo`），
  前端面板在 `.editor/ui.html` 的 `renderResources()`。**改完要重启编辑器**才会加载新后端。

## 卡片上的「格式 · 尺寸 · 大小」是自动算的

站长**不用填**这三个数（编辑器里也没有这些字段）：

- **格式**：`path.Ext` 从文件名推（`.mid` 显示成 MIDI）；
- **尺寸**：图片加载完，浏览器自己取 `naturalWidth / naturalHeight`；
- **大小**：页面把所有卡片文件一次性 `POST {cdn}/meta`，
  Worker（`board-api/functions/cdn/meta.js`）去 GitHub raw 读 `content-length` 回来。

拿不到就只显示格式，不影响下载/预览。别把这三个数字加回 `data/resources.toml`——
那是又要人维护一遍，2026-11-05 特意删过一次。

## 「从本站已有的图里选」

面板上除了「上传素材」（从本机选文件），还有一个 **「从本站已有的图里选」**：

- 列出 `static/` 下所有图片（约 390 张，缩略图目录和小图标会跳过），带搜索框；
- 点图多选，右上角选「导入到哪个分类」，点「导入选中」；
- 服务端 `POST /api/resources/import` 会把文件**复制**进素材仓库对应目录（不删原图），
  然后 commit + push；新条目落到清单里，保存后页面上就有了。

典型用法：放养区新加了一只宝可梦，`static/tbtak/sprite/xxx.png` 已经有了，
不用重新上传，在这儿勾一下就能进素材分发页。

## 行走图 / 脸图为什么是「拆出来的」

`static/tbtak/sprite/<id>.png` 是 `tools/build-tbtak.py` **重排**出来的网页精灵表
（4 行行走 + 1 行影子 + 1 行表情，合成在 96×96 的格子里），不是原图容器：

- 只有 下 / 左 / 右 三行，**原走图的「上」那一行没进表**；
- 每帧按九帧并集裁切、再按底边在格子里居中；
- 表情只放了被选用的那几格（原表情表 4×2 = 8 格，没用到的没进表）。

所以素材页上的 `<id>-walk.png` / `<id>-faces.png` 是
**`tools/split-tbtak-sprite.py` 从网页精灵表拆出来的可用版本**：

```
python3 tools/split-tbtak-sprite.py              # 输出到 /tmp/tbtak-split
python3 tools/split-tbtak-sprite.py --out 目录 --only fliegen,pontus
```

比例、脚底线、帧间对齐都保住了，能直接喂引擎；但**不等于**游戏工程
`Graphics/Characters` 与 `Graphics/Faces` 里的原文件。要分发原图，
从那边拿原件，用编辑器面板的「上传素材」传上去就行。


## 行序：3 列 × 4 行 = 下 / 左 / 右 / 上

RPG Maker 那张走图是 **3 列（左步 / 站中 / 右步）× 4 行（下 / 左 / 右 / 上）**，
和 `tools/build-tbtak.py` 里的 `ROW_DOWN/ROW_LEFT/ROW_RIGHT` 一致。
写说明、拆图、核对时都按这个顺序，别再记反。
