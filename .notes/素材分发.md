# 素材分发（GitHub 素材仓库 + 自建 CDN 反代）

主站页面：`content/resources.md` → `/resources/`，正文只有一个 `{{< resources >}}`。
数据在 `data/resources.toml`，样式在 `assets/css/retro.css` 的 `.res-*` 段，交互在 `static/js/resources.js`。

## 页面长什么样

- **宝可梦**（`sec = "pokemon"`）：按全国图鉴编号排的宝可梦图鉴。
  - 上面两排按钮：**世代**（只列真有素材的那几代）+ **图鉴编号**（只列真有的号，按钮上带名字）；
  - 点世代 → 只留那一代的卡片，并且自动切到这一页；点编号 → 只剩那一只；「全部编号」退回全代；
  - **一只一张卡片，这只的全部素材都挂在它身上**：行走图（走图动画）+ 脸图条 + 立绘缩略图；
    没有的那一项显示「暂时还没有 T^T…」；没有行走图但有立绘的，立绘直接当主预览；
  - 按钮：「下载这只」（行走图 + 脸图 + 全部立绘打成一个 zip）、「全部资源」（看详情）；
  - 点卡片打开**详情**：里面把这一只的素材各排成一张小卡片（缩略图 / 格式 · 尺寸 · 大小 /
    下载 / 看大图），底下「打包下载全部」；这和页面上的卡片是同一套样式；
  - 图鉴区顶上还有「去仓库下载全部素材（zip）」（GitHub 的 `archive/refs/heads/main.zip`）和「打开素材仓库」。
  - 没有全国图鉴号的（三代废稿「环兔儿」）排最后，徽章写「废稿」，不参与世代/编号筛选。
- **UI 素材 / MIDI**：一件素材一张卡片，跟以前一样。

**官方译名**：所有宝可梦一律用官方简体中文译名（谜拟丘、黑夜魔灵这种改过译名的要跟上），
别用自己编的或日文音译。手上有疑义就按官方来。

链接可以直接指到某一代 / 某一只：`/resources/#gen3`、`/resources/#dex393`。
（页面开着的时候改 hash 也会跟着切，不用刷新。）

## 为什么单独开一个仓库

素材（尤其是 500×500 立绘、点阵整张精灵表）会把主站仓库撑大（写这个时 `.git` 已经 152 MB，
`static/` 115 MB）。所以素材放独立仓库，主站只存一份清单：

- 素材仓库：<https://github.com/Arcarlight/Nijiboshi-Giveout-Storage>（public）
- 主站取文件的**主通道是自己的一层代理**：
  `https://nijiboshi-board.pages.dev/cdn/<路径>`
  → Cloudflare Pages Function `board-api/functions/cdn/[[path]].js` → `raw.githubusercontent.com`。
  好处：访客永远访问同一个域、永远能开；Cloudflare 边缘缓存一天，GitHub 只被打一次；
  只放行 `tbtak/{sprite,portrait,ui,face}/` 和 `audio/midi/` 五个前缀，不会被当成万能代理。
  （白名单在 `[[path]].js` 和 `meta.js` 里各有一份，**加目录要两边都改**。）
- **备用镜像**写在 `data/resources.toml` 的 `mirrors`：图片加载失败时页面按顺序换
  （fastly / gcore 两个 jsDelivr 节点，以及一个 GitHub 代理 ghproxy）。

### 为什么不用 jsDelivr 当主力

实测这个仓库的文件在 `cdn.jsdelivr.net` 上会 **301 跳到 `raw.githubusercontent.com`**，
国内打不开；同一时刻 `fastly.jsdelivr.net` 又可能是 200。时好时坏，所以
**主通道放自己的 Worker**，jsDelivr 只当备用。

## 素材仓库的目录约定

```
tbtak/sprite/    点阵图（行走图，整张精灵表）
tbtak/face/      脸图（表情条，一格 96×96）
tbtak/portrait/  对战立绘（敌人图，约 100–280px，四周空白已切）
tbtak/ui/        UI 素材（图标集、窗框、按钮底图）
audio/midi/      MIDI
```

目录变了要同步改两处：`data/resources.toml` 里的 `file` 路径（相对素材仓库根目录），
以及 `.editor/server.mjs` 里的 `GIVEOUT_DIRS`（上传走哪个目录）。

## 加一只宝可梦

1. 把行走图放进 `tbtak/sprite/`、脸图放进 `tbtak/face/`，`git push`；
2. 主站 `data/resources.toml` 里加一条：

```toml
[[items]]
sec   = "pokemon"                    # 固定是 pokemon
dex   = 393                          # 全国图鉴编号（数字，页面排序 / 世代筛选都靠它）
title = "波加曼"                      # 官方译名
file  = "tbtak/sprite/walk-pontus.png"        # 行走图（3 列 × 4 行），可以空
face  = "tbtak/face/pontus-faces.png"         # 脸图（4×2 表情表），选填；多张用英文逗号
art   = "tbtak/portrait/battler-pontus.png"   # 立绘，多个用英文逗号隔开，选填
note  = "脸图 4 个表情。原图 $WalkPontus.png；立绘原图 Enemy_Pontus.png"
```

3. 提交推送，GitHub Actions 部署完就出现在 `/resources/` 上。

编辑器的「工具 → 素材分发」面板里有两张表，宝可梦那张就是这几列，**不用手写 TOML**。

## 行走动画是怎么做的

精灵表固定是 **3 列（左步 / 站中 / 右步）× 4 行（下 / 左 / 右 / 上）**。
卡片上那个小动画没切图，纯 CSS：

- JS 先 `new Image()` 量出整张的宽高，一格 = 宽/3 × 高/4（**不是整数格就不套动画**，退回整张缩略图）；
- 把整张表当 `background-size: 300% 400%` 的背景，`background-position` 的百分比正好对应第几列 / 第几行
  （列：0 / 50 / 100%，行：0 / 33.33 / 66.67 / 100%）；
- `@keyframes res-walk-cycle`（`retro.css`）里 32 个关键帧：每个方向 3 帧 pingpong 两遍
  （`0,1,2,1,0,1,2,1`），四个方向依次来，一圈 4.2 秒；`step-end` 保证一格一格跳、不插值；
- 一格不是正方形也没事（露力丽是 32×45，动画框按比例变窄）；
- 只有滚进视口的卡片才加载 / 播放（`IntersectionObserver` 加 `.is-live`），滚出去暂停，省 CPU；
- 系统开了「减少动态效果」的不播动画，显示整张缩略图。

详情见 `static/js/resources.js` 的 `enhanceWalk()` 和 `retro.css` 的 `@keyframes res-walk-cycle`。

## 「下载这只」的 zip 是前端打的

不预先生成包，也不占素材仓库体积：点按钮时 `fetch` 这只的行走图 / 脸图原始字节，
用 `resources.js` 里的小 zip 写入器（store 不压缩 + CRC32）拼成 zip，`Blob` 直接下载。
包里还会塞一个 `署名.txt`（CC BY 要求的署名信息），文件名是 `No.393-波加曼.zip`。

「下载全部素材」直接用 GitHub 的 `archive/refs/heads/main.zip`，不用我们打包。

## 卡片上的「格式 · 整张尺寸 · 一格 · 大小」是自动算的

站长**不用填**这些数（编辑器里也没有这些字段）：

- **格式**：`path.Ext` 从文件名推（`.mid` 显示成 MIDI）；
- **尺寸**：图片加载完，浏览器自己取 `naturalWidth / naturalHeight`；宝可梦卡片再除以 3 / 4 报一格多大；
- **大小**：页面把所有卡片文件一次性 `POST {cdn}/meta`，
  Worker（`board-api/functions/cdn/meta.js`）去 GitHub raw 读 `content-length` 回来。

拿不到就只显示格式，不影响下载/预览。别把这些数字加回 `data/resources.toml`——
那是又要人维护一遍，2026-11-05 特意删过一次。

## 编辑器里怎么用（工具 → 素材分发）

- **页面文案**：开头三段、署名提示、授权说明、页脚补一句，存在 `[intro]` 里。
- **分类**：id（锚点，别乱改）/ 显示名 / 说明 / 整包下载链接。
- **宝可梦表**：预览 / 图鉴号 / 名字 / 行走图 / 脸图 / 说明。
  - 每行右边的「↑」= 传一张图，自动填进那一格（行走图进 `tbtak/sprite`，脸图进 `tbtak/face`）；
  - 「上传行走图（新建）」可以多选，一个文件一行新宝可梦，图鉴号和名字留给人填；
  - 「按图鉴号排序」把宝可梦部分按 `dex` 升序重排（页面上本来就按图鉴号排，这只是顺手整理 TOML）。
- **其它素材表**：「上传素材」旁边有个分类下拉（只列非 pokemon 的分类），上传 / 手动加一条都落在选中的分类。
- **从本站已有的图里选**：列 `static/` 下的图，勾选后**复制**进素材仓库对应目录并推送；
  目标是「点阵图行走图」时新加的是宝可梦行（只填 file），其余按普通素材加。
- **仓库状态**：顶部显示本机素材仓库路径、有没有未提交 / 没推的提交、用的哪个代理；
  推送失败不影响本机文件，点「推送」重试。

### 注意

- **`sections[0]` 现在是 `pokemon`**：面板里所有「默认第一个分类」的地方都得显式排除它，
  不然上传会往宝可梦表里塞东西、加出来的行还会从两张表里消失。改面板时留意这点。
- **保存只写 `data/resources.toml`**，要让页面生效还得「预览 / 发布」。
- 保存会重排文件、**只保留 `[meta]` 以上的注释**，想留话写在文件头部，别写在条目中间。
- **推送代理**沿用主站仓库里配给 github.com 的那个（`http.https://github.com/.proxy`），
  读的是 `git config`，换电脑只要那边配好代理，素材仓库这边不用重配。
- 服务端在 `.editor/server.mjs`（`/api/resources`、`/api/resources/upload`、`/api/resources/import`、`/api/resources/repo`），
  前端在 `.editor/ui.html` 的 `renderResources()`。**改完要重启编辑器**才会加载新后端。

## jsDelivr 的两个坑

1. **新文件**几分钟内可访问；**覆盖同名文件**可能还吃到旧缓存。
   想立刻生效：URL 里的 `@main` 换成 tag（如 `@v1`），或去
   <https://www.jsdelivr.com/tools/purge> 清一下。
   **最稳的做法是新版本换文件名**（`xxx-v2.png`），别覆盖。
2. 单文件别超 **20 MB**（jsDelivr 不保证；GitHub 硬上限 100 MB）。
   未缓存的文件首次请求会 301 到 raw.githubusercontent，属正常现象。

## 素材仓库里的 README / LICENSE

- `README.md` 是**给下载素材的人看的**：是什么、有什么、怎么署名、怎么下载。
  不要往里写维护步骤（那些写在本文档里）。
- `LICENSE` 是 CC BY 4.0 全文（从 <https://creativecommons.org/licenses/by/4.0/legalcode.txt> 取的）。

## 行走图 / 脸图为什么曾经是「拆出来的」

`static/tbtak/sprite/<id>.png` 是 `tools/build-tbtak.py` **重排**出来的网页精灵表
（4 行行走 + 1 行影子 + 1 行表情，合成在 96×96 的格子里），不是原图容器：

- 只有 下 / 左 / 右 三行，**原走图的「上」那一行没进表**；
- 每帧按九帧并集裁切、再按底边在格子里居中；
- 表情只放了被选用的那几格（原表情表 4×2 = 8 格，没用到的没进表）。

所以当时用 `tools/split-tbtak-sprite.py` 从网页精灵表拆出可用版本：

```
python3 tools/split-tbtak-sprite.py              # 输出到 /tmp/tbtak-split
python3 tools/split-tbtak-sprite.py --out 目录 --only fliegen,pontus
```

比例、脚底线、帧间对齐都保住了，能直接喂引擎；但**不等于**游戏工程
`Graphics/Characters` 与 `Graphics/Faces` 里的原文件。要分发原图，从那边拿原件，
用编辑器面板上传。**现在行走图和脸图都是原图了**：2026-11-08 补上了
波加曼 / 火稚鸡 / 木木枭的原表情表（`Actor2/3/4.png`，4×2 八格）和变隐龙
（`Merchant.png`，3 格），电飞鼠补了正脸 2 个 + 侧脸 3 个；旧的四张拆图
（`ignis/pontus/momoka/dryad-faces.png`）页面上已经不再引用，文件留在仓库里，
以前的链接不会断。

## 行序：3 列 × 4 行 = 下 / 左 / 右 / 上

RPG Maker 那张走图是 **3 列（左步 / 站中 / 右步）× 4 行（下 / 左 / 右 / 上）**，
和 `tools/build-tbtak.py` 里的 `ROW_DOWN/ROW_LEFT/ROW_RIGHT` 一致，
`@keyframes res-walk-cycle` 也是按这个行序排的（0% 下 → 25% 左 → 50% 右 → 75% 上）。
写说明、拆图、核对时都按这个顺序，别再记反。

## 哪些不发

**符利根（始祖小鸟）和虹星（沙漠蜻蜓）的素材不发**——那是剧情角色，不是通用宝可梦素材。
素材仓库里对应的 walk / faces / 立绘都已经撤掉（git 历史里还能翻回来）。
别再往素材页加回去。

## 名字怎么起：物种名，不写角色名

**同一物种的不同画稿都并入物种名下**：桃桃加的电飞鼠、某只波加曼、某只木木枭……
页面上只写「电飞鼠」「波加曼」「木木枭」，不写训练家名字；同一物种有多张画稿就并列几张卡，
说明里写原文件名区分。角色名只留在原文件名里（`Enemy_Momoka.png` 这种）。

**例外：虹星、符利根这种「本身就是角色」的**——它们不是某个物种的另一个画稿，
不能并进任何物种，也不发（见上一节）。

## 脸图的格式与文件名

- **格式固定是 RPG Maker 的脸图：4 列 × 2 行 = 8 格，一格 96×96（整张 384×192）。**
  表情不满 8 个就留透明的空格，**不要改成 1×N 或 4×3** —— RM 只认 4×2。
- 文件名用物种英文 slug：`tbtak/face/<slug>-faces.png`。一只表情超过 8 个就再开一张
  （`piplup-faces-2.png` 这种），`data/resources.toml` 的 `face` 用英文逗号分隔，
  页面上并排显示两张表。
- 改内容要**换文件名**：我们自己的 CDN 和 jsDelivr 都可能还缓存着同名旧图，
  习惯用 `-v2` 结尾（`zangoose-faces-v2.png`）。

## 对战立绘（`tbtak/portrait/`）

2026-11-05 加的 29 张，来自两个导出包（`Battlers.zip` 的 `Enemy_*.png` 25 张、
`PokemonResource.zip` 的 `*_source.PNG` 17 张）。

**立绘不单独成分类**：页面上的「立绘」分类已经撤掉，改成挂在对应宝可梦条目的 `art` 字段上
（一只宝可梦可能有多张立绘，逗号分隔）；只有没有图鉴号的（环兔儿）才单列一张卡。处理规则：

- **跨包重复**：12 只两边都有（Azumarill / Dunsparce / Goomy / Linoone / Litwick /
  Magnemite / Panpour / Pansage / Pansear / Pikachu / Warabitto / Zigzagoon）。
  裁掉透明边后逐像素比对，10 对完全相同；Pikachu 是 5 月旧稿 vs 9 月修订（取修订版），
  Warabitto 只差 2 个透明像素。统一取 `Enemy_*` 那份。
- **`*_source.PNG` 的空白边**：那是同一幅画放在 500×500 画布上，内容只占 9~25%，
  中身和 `Enemy_*` 一模一样；只有 source 包才有的 5 只（Xatu / Cranidos / Chatot /
  Druddigon / Dusknoir）是裁出来后发的。
- **切边**：所有图统一按 alpha 边界裁到底（`Image.split()[-1].getbbox()`），
  `Enemy_*` 里 Kurumayu / Momoka 本来也有余边，一起切了。裁完再断言四边都是内容。
- **文件名**：`battler-<slug>.png`；原文件名写在素材页的说明里。
- **谜拟Ｑ 有两版**（`Enemy_Mimikyu` 旧稿 128×120 / `Enemy_MimikyuRedo` 新版 172×158），
  只发了新版。
- **环兔儿**（`Enemy_Warabitto.png`）是三代废稿宝可梦，没有全国图鉴号，
  页面上不归类，排在立绘最后。
